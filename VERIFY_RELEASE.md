# Verify a LinuxCare Beta release

LinuxCare release artifacts include SHA256 checksums, an SPDX 2.3 Cargo SBOM, and GitHub artifact attestations when they are produced by the tagged GitHub Actions release workflow.

## 1. Verify downloaded checksums

Place the release files and `SHA256SUMS.txt` in the same directory, then run:

```bash
sha256sum -c SHA256SUMS.txt
```

Every downloaded artifact should report `OK`.

## 2. Verify GitHub build provenance

For the Debian package or binary archive built by the GitHub release workflow:

```bash
gh attestation verify linuxcare_0.7.0-beta.2_amd64.deb -R MilMit/LinuxCare
```

## 3. Verify the SPDX SBOM attestation

```bash
gh attestation verify linuxcare_0.7.0-beta.2_amd64.deb \
  -R MilMit/LinuxCare \
  --predicate-type https://spdx.dev/Document/v2.3
```

The repository identity must match the repository that published the release. Do not copy a repository value from an untrusted third-party download page.

## 4. Inspect the local release manifest

`RELEASE-MANIFEST.json` contains the expected SHA256 and size for each release asset generated by LinuxCare's packaging script. It complements, but does not replace, GitHub provenance verification.

## Trust boundary

A directly downloaded third-party `.deb` has system-level installation privileges. Only install a package after confirming that the source, checksums, and publisher are the ones you intended to trust.
