# LinuxCare 0.7.0-beta.2 — Debian Reliability Beta

LinuxCare 0.7.0-beta.2 is a reliability-focused follow-up to the first public Beta. The feature set remains frozen; this release concentrates on Debian package policy compliance, install/upgrade/remove safety, reproducible release metadata, and CI coverage across supported and preview Ubuntu environments.

## What changed since beta.1

- Fixed Debian package validation failures exposed by Lintian in CI.
- Replaced the obsolete `policykit-1` dependency with `polkitd` and declared the direct `libc6` runtime dependency.
- Added release-symbol stripping for the LinuxCare binaries.
- Added Debian copyright metadata and generated compressed `changelog.Debian.gz` package metadata.
- Added manual pages for `linuxcare` and `linuxcare-maintenance`.
- Reworked long Debian control-description lines to satisfy package policy checks.
- Changed helper shutdown in package maintainer scripts to use `deb-systemd-invoke`.
- Added systemd `Documentation=` metadata for the privileged helper service.
- Hardened package validation so these Debian policy regressions are caught before publication.
- Kept the setgid-directory packaging fix that explicitly normalizes the package staging tree and verifies `DEBIAN/` is mode `0755` immediately before `dpkg-deb`.

## Core Beta capabilities

- Safety-first Smart Cleaner with user-space Safety Quarantine, Undo, bounded retention, and Maintenance Timeline.
- System Health Score 2.0 and explainable Maintenance Center recommendations.
- Live Vitals, Process Intelligence, historical trends, and anomaly detection.
- Boot Doctor, Service Doctor, Package Doctor 2.0, Filesystem Doctor, Thermal & Power Doctor, Battery Lab 2.0, Hardware Doctor, and authenticated SMART/NVMe health.
- Network Doctor 3.0 plus Deep Network socket ownership and truthful eBPF readiness diagnostics.
- Storage Runway, Storage Intelligence, guarded filesystem throughput benchmark, Docker/Podman storage analysis, and read-only Btrfs/Snapper/Timeshift awareness.
- Real user-level systemd maintenance automation with optional desktop notifications.
- GNOME Shell top-bar extension with read-only live metrics and typed D-Bus power-profile control.

## Safety model

LinuxCare keeps the GTK application unprivileged. System-level operations are exposed through a narrow typed D-Bus/Polkit helper rather than a generic root shell. User-space cleanup eligible for Undo is moved to same-filesystem quarantine and is not counted as freed space until it is permanently purged.

Scheduled maintenance never performs privileged APT, Snap, Flatpak, journal, firewall, SMART mutation, or package-removal actions in the background. Deep Network does not capture packet payloads and does not persist remote endpoint history.

## Release verification

The tagged release workflow is required to pass the LinuxCare verification and packaging gates before GitHub publishes this prerelease. Those gates cover Rust formatting, `cargo check`, Clippy with warnings denied, unit tests, development and optimized builds, static/security regression checks, isolated 1024×600 GUI startup, Debian build and Lintian validation, staged install/upgrade/uninstall lifecycle checks, and a real root-level Debian upgrade/install/remove smoke test on Ubuntu 24.04.

CI also checks Rust 1.92 MSRV compatibility and reviews Ubuntu 26.04 preview compatibility separately.

## Optional runtime integrations

LinuxCare remains functional when optional tools are absent, but some diagnostics require them:

- `smartmontools` — authenticated SMART/NVMe health.
- `libnotify-bin` — desktop notification delivery.
- `bpftool` — richer eBPF readiness diagnostics; LinuxCare does not attach BPF programs in this Beta.
- `gnome-extensions` — explicit enable/disable management of the LinuxCare Vitals extension.

## Known Beta limitations

- Per-process network bandwidth remains intentionally unavailable until a real eBPF/cgroup accounting backend exists.
- SMART/NVMe health is read-only; LinuxCare does not run self-tests, firmware updates, sanitize, or format operations.
- Reclaimable container-storage figures are estimates and can differ from actual freed bytes because of shared layers and active references.
- Storage Runway requires sufficient history before it forecasts capacity pressure.
- A quarantined cleanup still consumes disk space until purge.
- The Snap definition remains development-oriented; the Full Edition currently relies on host Polkit/D-Bus/systemd integration and is not presented as a Store-equivalent replacement for the verified Debian package.

## Install

The preferred Beta artifact is the Debian package generated by the tagged release workflow:

```bash
sudo apt install ./linuxcare_0.7.0-beta.2_amd64.deb
```

The release also includes a binary tarball, deterministic source tarball, SPDX 2.3 SBOM, release manifest, SHA-256 checksums, and GitHub artifact attestations.

## Reporting issues

When reporting a bug, include the LinuxCare version, Ubuntu/GNOME version, reproduction steps, and only sanitized logs. Do not post passwords, tokens, private file contents, or unrelated personal paths.
